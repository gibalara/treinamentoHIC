# 1.9 · Seu projeto aprovado para as próximas trilhas (checklist de elegibilidade)

- **Trilha:** T1 · Arquiteto de Produto
- **Tempo:** 30 min
- **Evidência:** checklist aprovado
- **Status:** rascunho, ainda não cursado pelo aluno zero

## Por quê

Seu projeto acompanha você até a T6. Sem dados próprios, tarefa de IA ou vários tipos de usuário, as próximas trilhas não têm onde ser aplicadas.

O checklist de elegibilidade filtra isso agora, quando trocar ainda é barato. Ele é critério eliminatório do marco da T1.

## Demonstração

Exemplo: uma consultora sênior de RH que atende pequenas empresas. Produto: prepara a conversa de feedback a partir das anotações do gestor. O `SPEC.md` (especificação do produto) está no repositório `projeto-hic`.

1. Abra `projeto-hic` no modo de código do Claude Desktop (Claude Code), em **Manual**. Passo a passo em "Abrir uma pasta", na Referência da lição 0.4 da T0.
2. Cole o checklist (veja "Checklist de elegibilidade", na Referência) e peça: "Aplique este checklist ao SPEC.md. Para cada item, diga sim ou não, com o trecho que comprova."
3. Confira item a item:
   - Validado com 3 pessoas: resumo das conversas em `docs`.
   - Dados próprios para RAG (a IA responde com base em documentos próprios): guias de avaliação da consultora.
   - Tarefa de IA: rascunhar o roteiro de feedback.
   - Mais de um tipo de usuário: gestor e colaborador.
   - Ação de agente (IA que executa uma ação sozinha) com aprovação: lembrar o gestor e preparar rascunho para ele aprovar.
   - MVP cabe na T2b: `TASKS.md` sem IA, sem várias organizações e sem agente.
   - Sem dados sensíveis reais: MVP com dados fictícios.
4. Item reprovado: mais de uma organização. A seção 2 não citava as várias empresas clientes.
5. Peça a correção da seção 2 do `SPEC.md` e reaplique o item.
6. Peça: "Salve o checklist preenchido em docs/elegibilidade.md e faça um commit."

## Prática

1. Abra `projeto-hic` no Claude Code, em **Manual**.
2. Peça a aplicação do checklist ao `SPEC.md`, com o trecho que comprova cada item.
3. Confira cada resposta no arquivo citado.
4. Para cada item reprovado, siga "Item reprovado", na Referência.
5. Repita até todos os itens passarem.
6. Peça para salvar em `docs/elegibilidade.md`, fazer o commit e enviar ao GitHub.
7. Rode o Avaliador HIC (skill do curso que aplica a rubrica do marco) no repositório. [LACUNA: forma de entrega e instalação do Avaliador HIC não definidas na ementa]
8. Confira se a planilha de registro (lição 0.3 da T0) tem uma linha por lição da T1.

## Checagem

Entrega: `docs/elegibilidade.md` com os 8 itens aprovados e o trecho que comprova cada um, commitado.

## Referência

**Checklist de elegibilidade**

- [ ] Resolve um problema real do nicho, validado com pelo menos 3 pessoas
- [ ] Tem dados próprios que justificam RAG
- [ ] Tem pelo menos uma tarefa de IA clara
- [ ] Faz sentido com mais de um tipo de usuário
- [ ] Faz sentido para mais de uma organização: clientes, áreas ou departamentos (exigido na T5)
- [ ] Tem pelo menos uma ação que um agente poderia executar com aprovação humana
- [ ] O MVP cabe na T2b
- [ ] Não depende de dados sensíveis reais para funcionar

**Item reprovado**

| Item | Caminho |
| --- | --- |
| Validação | Completar as 3 conversas (lição 1.2b) |
| Dados próprios, tarefa de IA ou agente | Ajustar seção 6 do `SPEC.md`; se não houver como, trocar o problema (lição 1.2c) |
| Tipos de usuário ou organizações | Ajustar seção 2 do `SPEC.md` |
| MVP grande | Mover etapas para o `BACKLOG.md` (lição 1.7) |
| Dados sensíveis | Redesenhar com dados fictícios ou anonimizados (seção 5) |

**Rubrica do marco T1**

| Critério | Evidência | Eliminatório |
| --- | --- | --- |
| Problema validado com usuários reais | Resumo de 3 conversas | Sim |
| `SPEC.md` completo nas 8 seções | Arquivo no repositório | Sim |
| Checklist de elegibilidade aprovado | Checklist preenchido | Sim |
| Requisitos com critérios de aceite testáveis | Seção 4 do `SPEC.md` | Sim |
| Pré-validação com usuários sintéticos | Relatório da ferramenta | Não |
| Síntese com decisão explícita | Decisão justificada | Não |
| `TASKS.md` e `BACKLOG.md` separados | Arquivos | Não |
| Protótipo testado com 1 usuário | Link ou print | Não |
| Métrica de sucesso definida | Seção 3 do `SPEC.md` | Não |

**Termos**

- RAG: a IA responde com base nos seus documentos, com citação (T4)
- Agente: IA que executa uma ação sozinha; no curso, sempre com aprovação humana (T6)
- Organização: cliente, área ou departamento com dados isolados dos outros (T5)
- MVP: primeira versão usável, com o mínimo que resolve a dor
- Dado sensível: dado pessoal de saúde, origem, opinião, biometria e similares (LGPD)
