# 2b.3 · As tabelas que guardam os dados do seu produto (modelo de dados)

- **Trilha:** T2 · Builder (T2b · MVP do projeto próprio)
- **Tempo:** 60 min
- **Evidência:** diagrama + tabelas
- **Status:** rascunho, ainda não cursado pelo aluno zero

## Por quê

Tela se refaz em minutos; dado mal modelado contamina tudo o que vem depois. Mudar tabela com dados reais é a operação mais arriscada do produto.

O modelo de dados diz o que o produto guarda e como tudo se liga. Também diz quem é dono de cada linha. O dono é o que garante o isolamento entre usuários.

Você decide as tabelas a partir da seção 5 do `SPEC.md`. O Claude Code cria.

## Demonstração

Exemplo: o modelo de dados do Diário de Bordo.

1. Abra a pasta do Diário de Bordo no modo de código do Claude Desktop (ícone **</>**), em **Plano**.
2. Peça: "Leia a seção 5 do `SPEC.md` e proponha as tabelas: nome, campos, tipo de cada campo e ligações."
3. Confira a proposta contra o registro da jornada. A tabela `registros` precisa ter: trilha, lição, data, tempo, status, onde travou, aprendizado.
4. Confira o dono: cada registro tem o campo do usuário que o criou.
5. Confira a RLS (regra no banco que limita quais linhas cada usuário vê). Cada usuário só lê e altera os próprios registros.
6. Peça: "Desenhe o diagrama das tabelas em `docs/modelo-de-dados.md`, num formato que o GitHub mostra como imagem."
7. Abra o arquivo no GitHub e confira se o desenho bate com a proposta. [VERIFICAR NA INTERFACE]

9. No SQL Editor do Supabase, cole o SQL e rode, como na lição 2a.4. [VERIFICAR NA INTERFACE]

## Prática

1. Abra a pasta do seu projeto no modo de código, em **Plano**.
2. Peça a proposta de tabelas a partir da seção 5 do `SPEC.md` (veja "Pedido de modelo", na Referência).
3. Revise com o "Critério de modelo bom", na Referência. Peça ajustes até passar.
4. Peça o diagrama em `docs/modelo-de-dados.md` e confira no GitHub.
5. Troque para **Manual** e peça o SQL das tabelas, com RLS ativa em todas, num arquivo do repositório.
6. Rode o SQL no SQL Editor do Supabase e confira no Table Editor: tabelas criadas e RLS ativa.
7. Peça a explicação reversa: "Explique as tabelas e as regras de RLS do ponto de vista de risco."
8. Peça o commit com a mensagem "Cria modelo de dados".

## Checagem

Entrega: `docs/modelo-de-dados.md` com o diagrama + print do painel do Supabase com as tabelas e a RLS ativa.

## Referência

**Termos**

- Tabela: conjunto de linhas com os mesmos campos, como uma aba de planilha
- Campo: coluna da tabela, com um tipo (texto, número, data)
- Chave estrangeira: campo que liga uma linha a outra tabela; ex.: o dono do registro
- RLS: regra no banco que limita quais linhas cada usuário vê e altera
- Supabase: serviço com banco de dados e login, usado desde a lição 2a.4
- SQL: linguagem de comandos do banco; o Claude Code gera, você roda no SQL Editor do Supabase
- SQL Editor e Table Editor: telas do painel do Supabase para rodar SQL e ver tabelas
- Explicação reversa: o Claude Code explica o que gerou, do ponto de vista de arquitetura e risco

**Pedido de modelo**

- "Leia a seção 5 do `SPEC.md`. Proponha as tabelas do MVP: nome, campos, tipo, ligações e dono de cada linha. Só o que o `TASKS.md` usa. Não crie nada ainda."

**Critério de modelo bom**

- [ ] Cada funcionalidade do `TASKS.md` tem onde guardar o que usa
- [ ] Nenhuma tabela para funcionalidade do `BACKLOG.md`
- [ ] Toda tabela com dado de usuário tem o campo do dono
- [ ] RLS ativa em todas as tabelas
- [ ] Dado sensível listado na seção 5 do `SPEC.md` tem tratamento definido
- [ ] Nomes de tabela e campo legíveis por você

**Exemplo (Diário de Bordo)**

| Tabela | Campos principais | Dono |
| --- | --- | --- |
| `registros` | trilha, lição, data, tempo, status, onde travou, aprendizado | usuário que criou |

**Erros comuns**

- RLS ativa sem regra: ninguém vê nada. Peça a regra "cada usuário lê e altera os próprios registros"
- Tabela criada "para depois": apague e mova a ideia para o `BACKLOG.md`
- Mudar tabela que já tem dados: peça antes um plano que preserve os dados. Faça um commit só para a mudança
