# 2b.4 · Funcionalidades construídas uma a uma, com ponto seguro de volta (ciclos de construção)

- **Trilha:** T2 · Builder (T2b · MVP do projeto próprio)
- **Tempo:** 4–6 h
- **Evidência:** commits por funcionalidade
- **Status:** rascunho, ainda não cursado pelo aluno zero

## Por quê

Aqui o MVP ganha corpo. É a lição mais longa da trilha e a que mais sai do controle.

O ciclo do curso evita isso: Especificar → Gerar → Testar → Refinar, uma funcionalidade por vez. Cada ciclo fecha com um commit, o checkpoint para onde você volta se algo quebrar.

Se a construção passar de 6 horas, o MVP ficou grande. Corte para o `BACKLOG.md` em vez de insistir.

## Demonstração

Exemplo: um ciclo no Diário de Bordo, para a funcionalidade "filtrar registros por trilha".

1. Abra a pasta do Diário de Bordo no modo de código do Claude Desktop (ícone **</>**), em **Manual**.
2. **Especificar.** Peça: "Construa o filtro de registros por trilha. Critério de aceite: escolhida a T1, a lista mostra só registros da T1."
3. **Gerar.** Leia o plano que o Claude Code mostra e aprove as mudanças nos arquivos.
4. **Testar.** Peça para rodar o app no seu computador e abra o endereço local que ele indicar. [VERIFICAR NA INTERFACE]
5. Entre com a conta A, filtre por T1 e confira que só aparecem registros da T1.
6. Entre com a conta B e confirme que nenhum registro da conta A aparece.
7. **Refinar.** O filtro não volta para "todas". Peça o ajuste e teste de novo.
8. Peça a explicação reversa: "Explique o que mudou, do ponto de vista de arquitetura e risco."
9. Peça o commit: "Adiciona filtro de registros por trilha."
10. Registre o tempo do ciclo no Diário de Bordo.

## Prática

1. Abra o `PLANO.md` (lição 2b.1) e escolha a primeira etapa.
2. Se o projeto ainda não tem login, a primeira etapa é login + isolamento entre usuários (visto na lição 2a.5).
3. Rode um ciclo por etapa, como na Demonstração. Use o "Roteiro do ciclo", na Referência.
4. Teste cada funcionalidade com duas contas, A e B.
5. Feche cada ciclo com um commit e envie para o GitHub.
6. Quando algo quebrar, siga o protocolo de debugging (veja na Referência).
7. Marque a etapa como feita no `TASKS.md`.
8. Registre o tempo de cada ciclo. Ao passar de 6 horas somadas, pare e corte escopo.

## Checagem

Entrega: link do repositório no GitHub com um commit por funcionalidade do `TASKS.md` + soma do tempo registrado.

## Referência

**Termos**

- Ciclo: Especificar → Gerar → Testar → Refinar, fechado com um commit
- Checkpoint: commit que marca um ponto seguro para voltar
- Commit: versão salva da pasta; enviar para o GitHub guarda uma cópia na nuvem
- Endereço local: o app rodando só no seu computador, antes de publicar
- Isolamento entre usuários: um usuário nunca vê nem altera dados de outro
- Explicação reversa: o Claude Code explica o que gerou, do ponto de vista de arquitetura e risco

**Roteiro do ciclo**

1. Especificar: funcionalidade + critério de aceite do `SPEC.md`
2. Gerar: ler o plano, aprovar as mudanças
3. Testar: critério de aceite com conta A; isolamento com conta B
4. Refinar: um ajuste por pedido
5. Explicação reversa
6. Commit + envio ao GitHub
7. Tempo registrado

**Pedidos ao Claude Code**

- Construir: "Construa [funcionalidade]. Critério de aceite: [critério do `SPEC.md`]. Mostre o plano antes."
- Rodar: "Rode o app no meu computador e me diga o endereço."
- Voltar: "Volte o projeto para o último commit."
- Salvar: "Faça um commit com a mensagem '[o que mudou]' e envie para o GitHub."

**Protocolo de debugging (lição 2a.6)**

1. Reproduzir o erro
2. Pedir hipóteses ao Claude Code
3. Testar uma hipótese por vez
4. Corrigir num commit só com a correção
5. Registrar causa e solução no `CLAUDE.md`

**Sinais de MVP grande**

- Soma dos ciclos acima de 6 horas
- Funcionalidade que pede outra para fazer sentido
- Ciclo que não fecha em um commit
- Ação: mover para o `BACKLOG.md` e registrar a decisão na seção 8 do `SPEC.md`

**Erros comuns**

- Pedir três funcionalidades num pedido: o teste fica impossível; um ciclo por vez
- Testar só com uma conta: o isolamento falha sem você ver
- Seguir sem commit: o próximo erro leva junto o que funcionava
