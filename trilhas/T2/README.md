# T2 · Builder

Esforço: 16–24 h · Badge: Builder

## Objetivo mensurável

Publicar um MVP com login, isolamento entre usuários e testes automatizados.

## Vitória de abertura

Claude Code construindo uma tela funcional a partir de uma frase.

## Lições

### T2a · Ensaio guiado: Diário de Bordo HIC

- 2a.1 · Um plano de construção revisado antes do código (modo Plano)
- 2a.2 · Regras que o Claude Code segue em toda sessão (`CLAUDE.md`)
- 2a.3 · A tela de registro da sua jornada funcionando (primeira tela)
- 2a.4 · Seus registros da T0 e da T1 guardados no app (banco de dados no Supabase)
- 2a.5 · Login e cada usuário vendo só os próprios registros (autenticação e permissões)
- 2a.6 · Um erro resolvido com método e registrado para não voltar (protocolo de debugging)
- 2a.7 · Seu avanço no curso em números numa tela (painel)
- 2a.8 · Seu Diário no ar, com endereço público e segredos protegidos (deploy na Vercel)

### T2b · MVP do projeto próprio

- 2b.1 · O caminho do seu MVP em etapas verificáveis (plano do MVP)
- 2b.2 · Regras que o Claude Code segue no seu projeto (`CLAUDE.md`)
- 2b.3 · As tabelas que guardam os dados do seu produto (modelo de dados)
- 2b.4 · Funcionalidades construídas uma a uma, com ponto seguro de volta (ciclos de construção)
- 2b.5 · Critérios de aceite conferidos sozinhos a cada mudança (testes automatizados)
- 2b.6 · Brechas encontradas e corrigidas antes de publicar (revisão de segurança)
- 2b.7 · Seu MVP no ar, com endereço público (deploy em produção)
- 2b.8 · Fricções de uso encontradas antes do usuário real (usabilidade com agentes externos)
- 2b.9 · Seu MVP nas mãos de quem tem o problema (teste com usuário real)
- 2b.10 · Versão 1 fechada e próximo passo definido (notas da versão e backlog)

## Marco

MVP no ar, testado por usuário real. Rubricas: [`rubricas/T2a.md`](../../rubricas/T2a.md) e [`rubricas/T2b.md`](../../rubricas/T2b.md).
