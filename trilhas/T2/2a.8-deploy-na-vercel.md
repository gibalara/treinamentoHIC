# 2a.8 · Seu Diário no ar, com endereço público e segredos protegidos (deploy na Vercel)

- **Trilha:** T2 · Builder (T2a · Ensaio guiado: Diário de Bordo HIC)
- **Tempo:** 45 min
- **Evidência:** URL pública
- **Status:** rascunho, ainda não cursado pelo aluno zero

## Por quê

Até aqui, o Diário só roda no seu computador. O deploy publica o app num endereço que qualquer pessoa abre pelo navegador.

A Vercel é o serviço de publicação do curso. Ela pega o código do GitHub e recebe os segredos à parte, como variáveis de ambiente.

Aqui você verifica, no app publicado, os quatro eliminatórios do marco T2a: app no ar, login, isolamento e segredos.

## Demonstração

Exemplo: o Diário de Bordo de referência, com painel pronto e tudo enviado ao GitHub.

1. Abra a pasta `diario-de-bordo` no modo de código, em **Plano**, e peça: "Planeje a etapa 'deploy na Vercel'. Liste as variáveis de ambiente que preciso cadastrar lá, sem os valores." [VERIFICAR NA INTERFACE]
2. No site da Vercel, crie um projeto a partir do repositório `diario-de-bordo` do GitHub. [VERIFICAR NA INTERFACE: autorização de acesso ao GitHub]
3. Nas configurações do projeto na Vercel, cadastre cada variável da lista, copiando os valores do `.env.local` pelo editor. [VERIFICAR NA INTERFACE]
4. Mande publicar e espere o fim. Copie a URL pública. [VERIFICAR NA INTERFACE]
5. No painel do Supabase, cadastre a URL pública nas configurações de login. [VERIFICAR NA INTERFACE: nome da configuração de URL do site]
6. Abra a URL numa janela anônima do navegador. Entre com a conta A e confira registros e painel.
7. Refaça o "Teste com duas contas" (Referência da lição 2a.5) na URL pública.
8. Peça ao Claude Code: "Procure no repositório e no histórico de commits qualquer chave, senha ou credencial escrita no código."
9. No GitHub, confira que o `.env.local` não está no repositório.
10. Preencha o "Roteiro dos eliminatórios", na Referência desta lição.
11. Peça: "Registre a URL no README e faça o commit 'Publica o Diário'." README é a apresentação do repositório. Envie ao GitHub.
12. Na Vercel, confira que o envio gerou uma publicação nova. [VERIFICAR NA INTERFACE]

## Prática

1. Em **Plano**, peça a etapa "deploy na Vercel" e a lista de variáveis.
2. Crie o projeto na Vercel a partir do seu repositório `diario-de-bordo`. [VERIFICAR NA INTERFACE]
3. Cadastre as variáveis de ambiente na Vercel e publique.
4. Cadastre a URL pública nas configurações de login do Supabase. [VERIFICAR NA INTERFACE]
5. Preencha o "Roteiro dos eliminatórios" (Referência desta lição) na URL pública, item por item.
6. Corrija o que falhar com o protocolo de debugging da lição 2a.6 e refaça o item.
7. Confira os não eliminatórios, na Referência desta lição.
8. Registre a URL no README, faça o commit e envie ao GitHub.
9. Rode o Avaliador HIC no repositório. [LACUNA: skill Avaliador HIC ainda não construída]
10. Registre esta lição no Diário, já pela URL pública.

## Referência

**Termos**

- Deploy: publicar o app na internet
- Vercel: serviço que publica o app a partir do repositório no GitHub
- URL pública: endereço do app que abre em qualquer computador
- Variável de ambiente: valor guardado fora do código, cadastrado na Vercel e lido pelo app
- Janela anônima: janela do navegador sem login salvo
- README: arquivo de apresentação do repositório

**O que você faz em cada lugar**

| Onde | O quê |
| --- | --- |
| Vercel | Criar o projeto, cadastrar variáveis, publicar, copiar a URL |
| Supabase | Cadastrar a URL pública nas configurações de login |
| GitHub | Conferir que nenhum `.env` foi enviado |
| Claude Code | Listar variáveis, procurar segredos, atualizar o README |

**Roteiro dos eliminatórios (marco T2a)**

| Critério | Como verificar | Evidência |
| --- | --- | --- |
| App publicado | URL abre numa janela anônima | URL + print |
| Login operante | Sem login, a tela manda para o login; conta A entra | Prints |
| Isolamento entre usuários | "Teste com duas contas" (lição 2a.5) na URL pública | Teste preenchido |
| Segredos fora do código | Busca do Claude Code sem achados; `.env.local` ausente no GitHub; variáveis cadastradas na Vercel | Resposta da busca + prints |

**Não eliminatórios**

- [ ] Registros da T0 e da T1 importados (lição 2a.4)
- [ ] Um commit por ciclo verificável no histórico
- [ ] `CLAUDE.md` com pelo menos um erro registrado (lição 2a.6)

**Pedidos ao Claude Code**

- Variáveis: "Liste as variáveis de ambiente que preciso cadastrar na Vercel, sem os valores."
- Segredos: "Procure no repositório e no histórico de commits qualquer chave, senha ou credencial escrita no código."
- Histórico: "Liste os commits com mensagem e data." (para conferir um commit por ciclo)

**Erros comuns**

| Erro | Causa provável | O que fazer |
| --- | --- | --- |
| Funciona local, falha na URL | Variável faltando na Vercel | Comparar a lista de variáveis com o cadastro; publicar de novo |
| Login redireciona para endereço local | URL pública não cadastrada no Supabase | Cadastrar a URL [VERIFICAR NA INTERFACE] |
| Segredo encontrado no histórico | Chave foi commitada antes | Trocar a chave no Supabase e pedir ao Claude Code para retirá-la do código [VERIFICAR NA INTERFACE: onde gerar chave nova] |
