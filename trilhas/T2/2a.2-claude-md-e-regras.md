# 2a.2 · Regras que o Claude Code segue em toda sessão (`CLAUDE.md`)

- **Trilha:** T2 · Builder (T2a · Ensaio guiado: Diário de Bordo HIC)
- **Tempo:** 45 min
- **Evidência:** arquivo commitado
- **Status:** rascunho, ainda não cursado pelo aluno zero

## Por quê

O Claude Code não lembra das conversas anteriores. Sem regras escritas, cada sessão pode colocar uma senha no código ou pular um teste.

O `CLAUDE.md` é o arquivo de regras do projeto. O Claude Code o lê no início de toda sessão naquela pasta.

Com ferramentas e testes, ele forma o harness: o conjunto que mantém o Claude Code no trilho.

Exemplo: o Diário de Bordo de referência, com `SPEC.md` e `PLANO.md` já no repositório.

9. Confira a resposta: ele deve recusar e propor uma variável de ambiente.

## Prática

1. Abra a pasta `diario-de-bordo` no modo de código, em **Manual**.
2. Peça o `CLAUDE.md` a partir do "Modelo de `CLAUDE.md`".
3. Acrescente uma regra sua, vinda da revisão do `PLANO.md` na lição 2a.1.
4. Peça o `.gitignore` que bloqueia arquivos `.env`.
5. Faça o commit e envie ao GitHub.
6. Numa sessão nova, pergunte quais regras ele segue.
7. Teste a regra de segredos com o pedido do passo 8 da Demonstração.
8. Se ele não recusar, peça para reforçar a regra no `CLAUDE.md` e teste de novo.
9. Registre esta lição na planilha de registro.

## Checagem

Entrega: link do commit com o `CLAUDE.md` e o `.gitignore`, mais a resposta do teste de segredos.

## Referência

**Termos**

- `CLAUDE.md`: arquivo de regras que o Claude Code lê em toda sessão na pasta
- Harness: `CLAUDE.md` + regras + ferramentas + testes
- Segredo: senha ou chave que dá acesso a um sistema
- Variável de ambiente: valor guardado fora do código, lido pelo app ao rodar
- Arquivo `.env`: arquivo local com as variáveis de ambiente; nunca vai ao GitHub
- `.gitignore`: lista de arquivos que o git não salva nem envia

**Modelo de `CLAUDE.md`**

```markdown
# CLAUDE.md — Diário de Bordo

## Produto
- Fonte de verdade: SPEC.md. Plano: PLANO.md.
- Fora do escopo: IA, papéis e integrações.

## Segurança
- Segredos só em variáveis de ambiente. Nunca no código, nunca no GitHub.
- Arquivos .env ficam no .gitignore.
- Toda chamada de IA no servidor (vale a partir da T4).
- Cada usuário só vê os próprios dados, garantido no banco.

## Forma de trabalhar
- Plano antes de cada etapa nova.
- App básico antes de multiusuário.
- Um commit por ciclo verificável, mensagem curta no imperativo.
- Depois de cada geração relevante, explicar o arquivo do ponto de vista de arquitetura e risco.

## Debugging
- Protocolo: reproduzir → hipóteses → testar uma → corrigir com commit isolado → registrar aqui.

```

**Pedidos ao Claude Code**

- Criar: "Crie um CLAUDE.md com as regras abaixo. Não acrescente regras sem me perguntar."
- Conferir: "Quais regras você segue neste projeto?"
- Reforçar: "Você descumpriu a regra [regra]. Reescreva-a no CLAUDE.md para não se repetir."

**Erro comum:** regra vaga ("cuide da segurança") não muda o comportamento. Escreva o que fazer e o que nunca fazer.
