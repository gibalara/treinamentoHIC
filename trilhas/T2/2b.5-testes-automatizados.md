# 2b.5 · Critérios de aceite conferidos sozinhos a cada mudança (testes automatizados)

- **Trilha:** T2 · Builder (T2b · MVP do projeto próprio)
- **Tempo:** 75 min
- **Evidência:** testes passando
- **Status:** rascunho, ainda não cursado pelo aluno zero

## Por quê

Cada pedido ao Claude Code pode quebrar algo que já funcionava. Testar tudo à mão a cada mudança não escala.

Um teste automatizado é um pequeno programa que confere um critério de aceite e diz "passou" ou "falhou". Você roda todos com um pedido.

Os testes nascem dos critérios de aceite da seção 4 do `SPEC.md`. Você não escreve o teste; você confere se ele testa o que o critério diz.

## Demonstração

Exemplo: testes do Diário de Bordo para o critério "cada usuário só vê os próprios registros".

1. Abra a pasta do Diário de Bordo no modo de código do Claude Desktop (ícone **</>**), em **Manual**.
2. Peça: "Liste os critérios de aceite da seção 4 do `SPEC.md` e proponha um teste automatizado para cada um."
3. Confira se o critério de isolamento está na lista: usuário A não lê registros do usuário B.
4. Peça para criar os testes e rodá-los. Aprove as mudanças.
5. Leia o resultado: quantos passaram e quantos falharam.
6. Peça: "Explique em português o que o teste de isolamento faz, passo a passo."
7. Confira se a explicação bate com o critério do `SPEC.md`.
8. Prova de que o teste funciona: peça para desligar de propósito a regra de isolamento e rodar de novo.
9. Confirme que o teste de isolamento falhou. Peça para voltar a regra ao último commit e rodar de novo.
10. Com todos passando, peça o commit: "Adiciona testes dos critérios de aceite."

## Prática

1. Abra a pasta do seu projeto no modo de código, em **Manual**.
2. Peça a lista de critérios de aceite e um teste por critério (veja "Pedido de testes", na Referência).
3. Confira se cada funcionalidade principal do `TASKS.md` tem pelo menos um teste.
4. Confira se existe teste de isolamento entre usuários.
5. Peça para criar e rodar os testes.
6. Escolha dois testes e peça a explicação em português. Confira contra o `SPEC.md`.
7. Quebre de propósito uma regra coberta, veja o teste falhar e volte ao último commit.
8. Com todos passando, peça o commit e envie para o GitHub.
9. Acrescente ao `CLAUDE.md` a regra: "Rodar todos os testes antes de cada commit."

## Checagem

Entrega: print ou texto do resultado da execução com todos os testes passando + lista "critério de aceite → teste".

## Referência

**Termos**

- Teste automatizado: programa que confere um comportamento e responde "passou" ou "falhou"
- Critério de aceite: condição verificável que diz se a funcionalidade está pronta (seção 4 do `SPEC.md`)
- Regressão: algo que funcionava e parou depois de uma mudança
- Commit: versão salva da pasta, ponto seguro para voltar
- `CLAUDE.md`: arquivo de regras que o Claude Code lê ao abrir a pasta
- [LACUNA: ferramenta de testes de referência não definida na ementa; o Claude Code escolhe conforme o projeto]

**Pedido de testes**

- "Liste os critérios de aceite da seção 4 do `SPEC.md`. Crie um teste automatizado para cada um, incluindo isolamento entre usuários. Rode todos e mostre o resultado."

**Pedidos ao Claude Code**

- Rodar: "Rode todos os testes e mostre o resultado."
- Entender: "Explique em português o que o teste [nome] faz."
- Provar: "Desligue de propósito [regra] e rode os testes."
- Voltar: "Volte o projeto para o último commit."

**Tabela critério → teste**

| Critério de aceite (`SPEC.md`) | Teste | Resultado |
| --- | --- | --- |
| [critério] | [nome do teste] | passou / falhou |

**Erros comuns**

- Teste que sempre passa: não prova nada. Quebre a regra e confirme que ele falha
- O Claude Code ajusta o teste para passar: peça para corrigir o app, não o teste
- Teste que depende de dados reais: peça dados fictícios criados pelo próprio teste
