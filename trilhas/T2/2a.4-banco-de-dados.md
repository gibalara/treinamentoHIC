# 2a.4 · Seus registros da T0 e da T1 guardados no app (banco de dados no Supabase)

- **Trilha:** T2 · Builder (T2a · Ensaio guiado: Diário de Bordo HIC)
- **Tempo:** 75 min
- **Evidência:** registros anteriores visíveis
- **Status:** rascunho, ainda não cursado pelo aluno zero

## Por quê

Sem banco de dados, o registro some quando a página recarrega. O banco guarda os dados fora da tela, de forma permanente.

O Supabase é o serviço de banco do curso; na lição 2a.5, ele também cuida do login. Você cria o projeto no painel dele e o Claude Code liga o app ao banco.

Aqui sua planilha da T0 e da T1 entra no app. Daqui em diante, o registro da jornada vai para o Diário.

## Demonstração

Exemplo: o Diário de Bordo de referência, com a tela de registro pronta e sem banco.

1. No site do Supabase, crie um projeto chamado `diario-de-bordo`. Guarde a senha do banco num gerenciador de senhas, fora do repositório. [VERIFICAR NA INTERFACE]
2. Abra a pasta `diario-de-bordo` no modo de código, em **Plano**, e peça: "Planeje a etapa 'banco de dados' do PLANO.md. A tabela de registros tem os 7 campos da tela. Gere o SQL num arquivo do repositório; eu rodo no painel do Supabase."
3. Confira o plano e troque para **Manual**. Peça a execução.
4. Peça: "Crie o arquivo .env.local com os nomes das variáveis do Supabase, sem valores. Confirme que ele está no .gitignore." O `.env.local` guarda segredos só no seu computador.
5. No painel do Supabase, copie a URL do projeto e a chave pública. Nunca a chave secreta. [VERIFICAR NA INTERFACE: nome e local das chaves]
6. Abra o `.env.local` no editor e cole os valores. Não cole chaves na conversa com o Claude Code.
7. No SQL Editor do Supabase, cole o conteúdo do arquivo SQL e rode. Confira a tabela no Table Editor. [VERIFICAR NA INTERFACE]
8. Exporte a planilha de registro como CSV (planilha salva como texto) e salve em `importacao/`, na pasta do projeto. [VERIFICAR NA INTERFACE: opção de exportar CSV na sua planilha]
9. Peça: "Ponha a pasta importacao no .gitignore. Ajuste o CSV aos nomes e formatos das colunas da tabela. Remova as linhas de cadência e datas-alvo."
10. No Table Editor, importe o CSV ajustado na tabela de registros. [VERIFICAR NA INTERFACE: opção de importar CSV]
11. Peça: "Ligue a tela à tabela: listar e gravar registros." Peça para rodar o app e abra o endereço.
12. Confira os registros da T0 e da T1 na tela. Crie um novo, recarregue e veja que ele permanece.
13. Peça a explicação reversa e depois: "Liste os arquivos que vão entrar no commit." O `.env.local` não pode aparecer.
14. Peça: "Faça um commit com a mensagem 'Liga a tela ao banco e importa registros'."

## Prática

1. Crie o projeto `diario-de-bordo` no Supabase. [VERIFICAR NA INTERFACE]
2. Em **Plano**, peça a etapa "banco de dados" e revise.
3. Em **Manual**, peça a execução e o `.env.local` com os nomes das variáveis, sem valores.
4. Cole a URL e a chave pública no `.env.local`, pelo editor. Nada de chave na conversa.
5. Rode o SQL no SQL Editor e confira a tabela.
6. Exporte sua planilha como CSV para `importacao/` e peça o ajuste (Demonstração, passo 9).
7. Importe o CSV no Table Editor.
8. Peça a ligação da tela ao banco e confira seus registros anteriores.
9. Grave o registro desta lição no Diário, recarregue e confira que ele permanece.
10. Confira que o `.env.local` fica fora do commit. Faça o commit e envie ao GitHub.
11. A planilha se aposenta: daqui em diante, registre cada lição no Diário.

## Referência

**Termos**

- Banco de dados: onde o app guarda os dados de forma permanente
- Supabase: serviço de banco de dados (Postgres, um tipo de banco) e de login usado no curso
- Tabela: conjunto de linhas e colunas no banco, como uma aba de planilha
- SQL: linguagem de comandos do banco; o Claude Code escreve, você roda no painel
- SQL Editor: tela do Supabase onde se roda SQL
- Table Editor: tela do Supabase onde se veem e importam dados
- CSV: planilha salva como texto, com colunas separadas por vírgula
- Chave pública: chave que o app usa no navegador; os dados ficam protegidos pelas regras do banco (lição 2a.5)
- Chave secreta: dá acesso total ao banco; não entra no app nem no `.env.local` da T2a [VERIFICAR NA INTERFACE: nome das chaves no painel do Supabase]
- `.env.local`: arquivo local com as variáveis de ambiente; fica fora do GitHub

**O que você faz em cada lugar**

| Onde | O quê |
| --- | --- |
| Painel do Supabase | Criar projeto, copiar URL e chave, rodar SQL, importar CSV |
| Editor | Colar valores no `.env.local` |
| Claude Code | Planejar, gerar SQL, ajustar CSV, ligar tela e banco, commit |

**Pedidos ao Claude Code**

- Variáveis: "Crie o .env.local com os nomes das variáveis, sem valores. Confirme que está no .gitignore."
- SQL: "Gere o SQL da tabela num arquivo do repositório; eu rodo no painel."
- Importação: "Ajuste o CSV aos nomes e formatos das colunas da tabela."
- Conferir commit: "Liste os arquivos que vão entrar no commit."

**Erros comuns**

| Erro | Causa provável | O que fazer |
| --- | --- | --- |
| Importação recusa linhas | Data ou tempo em formato diferente | Pedir o ajuste do CSV de novo, citando a coluna |
| Dados no painel, tela vazia | Regra de acesso do banco bloqueando a leitura [VERIFICAR: comportamento padrão de tabela nova no Supabase] | Pedir hipóteses ao Claude Code; não desligar a proteção sem entender |
| `.env.local` aparece no commit | Faltou o `.gitignore` | Parar e pedir para retirá-lo antes do commit |
| Não acho o `.env.local` na pasta | Arquivo que começa com ponto pode ficar oculto | No Explorador de Arquivos, mostrar itens ocultos [VERIFICAR NA INTERFACE] |
| Claude Code pede a chave secreta | Pedido fora do escopo da T2a | Recusar; usar só a chave pública |

- Até a lição 2a.5, a tabela não separa usuários. Use só seus dados da jornada.
