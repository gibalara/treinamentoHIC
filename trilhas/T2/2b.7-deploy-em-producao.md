# 2b.7 · Seu MVP no ar, com endereço público (deploy em produção)

- **Trilha:** T2 · Builder (T2b · MVP do projeto próprio)
- **Tempo:** 45 min
- **Evidência:** URL pública
- **Status:** rascunho, ainda não cursado pelo aluno zero

## Por quê

Enquanto o MVP roda só no seu computador, ninguém mais consegue usá-lo. As lições 2b.8 e 2b.9 dependem de um endereço público.

Deploy é publicar o app na internet. Produção é a versão que usuários reais acessam; erro ali é visto por eles.

Você já publicou o Diário de Bordo na lição 2a.8. Agora repete o caminho, e o teste com duas contas passa a valer no endereço público.

## Prática

1. Confira os pré-requisitos (veja "Antes de publicar", na Referência).
2. Peça a lista de variáveis de ambiente de produção, só os nomes.
3. Crie o projeto na Vercel a partir do repositório e cadastre as variáveis. [VERIFICAR NA INTERFACE]
4. Publique, copie a URL pública e cadastre-a nas configurações de login do Supabase.
5. Teste cada critério de aceite do `SPEC.md` na URL pública.
6. Faça o teste com duas contas, como na Demonstração, passos 8 a 10.
7. Registre a URL no `README.md` do projeto e peça o commit.

## Checagem

Entrega: URL pública + teste com duas contas nesse endereço (o que A fez, o que B não viu).

## Referência

**Termos**

- Deploy: publicar o app na internet
- Produção: a versão publicada, usada por pessoas reais
- URL: endereço da página na internet
- Vercel: serviço que publica o app a partir do repositório do GitHub
- Variável de ambiente: valor guardado fora do código, como uma chave; cadastrado na Vercel, não no GitHub
- `.env.local`: arquivo no seu computador com os valores das variáveis; nunca vai ao GitHub (lição 2a.4)
- Janela anônima: janela do navegador sem login salvo; com uma janela normal, permite testar duas contas ao mesmo tempo
- `README.md`: arquivo de apresentação do repositório, mostrado na página inicial dele no GitHub
- Protocolo de debugging: roteiro fixo para resolver erros (lição 2a.6; resumo na Referência da lição 2b.4)

**Erros comuns**

- App publicado abre em branco ou dá erro: falta variável de ambiente na Vercel
- Login em produção volta para o endereço local: falta cadastrar a URL pública no Supabase [VERIFICAR NA INTERFACE]
- Valor de segredo colado no chat ou num arquivo: troque a chave e cadastre só na Vercel
