# 0.5 · Salvar, voltar versões e entender o código gerado (git e leitura de código)

- **Trilha:** T0 · Pré-voo
- **Tempo:** 75 min
- **Evidência:** primeiro commit + quiz de erros

## Por quê

O Claude Code erra e, às vezes, estraga o que funcionava. O git guarda versões: cada commit é um ponto seguro para voltar.

Você não escreve código, mas lê e audita o que foi gerado. Em app de consumo, há quem dispense isso. Em empresa e produto regulado, é obrigatório.

Terminal, caminhos e comandos ficam na Referência, para quando forem necessários.

## Demonstração

Exemplo: um profissional sênior com uma calculadora de custo de reunião numa pasta aberta no Claude Code.

1. Peça: "Faça um commit com a mensagem 'Cria calculadora de custo de reunião'."
2. No GitHub, crie um repositório privado e vazio. Copie o endereço dele. [VERIFICAR NA INTERFACE]
3. Peça: "Conecte esta pasta ao repositório [endereço] e envie o commit." [VERIFICAR NA INTERFACE: autorização de acesso ao GitHub]
4. Abra o repositório no GitHub e confira o arquivo.
5. Peça uma mudança ruim de propósito: "Troque todos os textos da página para inglês."
6. Abra a página e veja o resultado indesejado.
7. Peça: "Volte o arquivo para a versão do último commit."
8. Recarregue a página e confirme que a versão anterior voltou.
9. Peça: "Explique este arquivo do ponto de vista de arquitetura e risco."

## Prática

1. Abra no Claude Code a pasta do utilitário da 0.4.
2. Peça o primeiro commit, com mensagem curta no imperativo.
3. Crie um repositório privado no GitHub e envie o commit. [VERIFICAR NA INTERFACE]
4. Confira no GitHub se o arquivo está lá.
5. Peça uma mudança, veja o resultado e peça para voltar à versão anterior.
6. Peça a explicação reversa do seu utilitário.
7. Anote um risco que você não tinha visto.

## Checagem

Entrega: link do repositório no GitHub com o primeiro commit.

Quiz de erros:

1. Uma mudança quebrou o utilitário. Qual é o caminho mais rápido de volta?
2. O GitHub não deixa criar uma pasta vazia pela web. Por quê, e como contornar?
3. O `cd` no PowerShell retorna "Não é possível localizar um parâmetro posicional". Qual é a causa provável?
4. O repositório no OneDrive mostra erro de `index.lock`. O que fazer?
5. Por que pedir a explicação reversa, se você não escreve código?

## Referência

**Pedidos ao Claude Code**

- Salvar: "Faça um commit com a mensagem '[o que mudou]'."
- Enviar: "Envie os commits para o GitHub."
- Voltar: "Volte [arquivo] para a versão do último commit."
- Explicação reversa: "Explique este arquivo do ponto de vista de arquitetura e risco."
- Regra: um commit por mudança verificável

**Terminal (só quando precisar)**

| Comando | Para |
| --- | --- |
| `cd "C:\caminho com espaços"` | Entrar numa pasta |
| `git status` | Ver o que mudou |
| `git log --oneline` | Ver os commits |
| `git add .` e `git commit -m "Mensagem"` | Salvar uma versão |
| `git push` | Enviar ao GitHub |
| `git restore arquivo` | Descartar mudança ainda não salva |

**Erros comuns (Tutor HIC)**

| Erro | Causa | Solução |
| --- | --- | --- |
| Pasta vazia no GitHub pela web | O GitHub não guarda pastas vazias | Add file > Create new file, digitar "pasta/arquivo.md" |
| "Não é possível localizar um parâmetro posicional" no `cd` | Espaços no caminho | Caminho entre aspas, ou Claude Code no Desktop |
| `index.lock` ou arquivos duplicados | Sincronização do OneDrive | Pausar a sincronização ou manter o repositório fora do OneDrive |
